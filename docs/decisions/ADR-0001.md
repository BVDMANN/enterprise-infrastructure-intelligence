# ADR-0001 — Monolithe modulaire + Control Plane / Data Plane

- **Statut :** Accepté (2026-11-24, PHASE 0)
- **Contexte :** la plateforme doit servir des ETI et grandes entreprises
  avec des environnements hybrides, tout en restant développable par une
  petite équipe initiale. La tentation des microservices dès le départ
  créerait une complexité opérationnelle (déploiement, observabilité,
  transactions distribuées) sans bénéfice mesuré.
- **Décision :**
  - Architecture **monolithe modulaire** : un seul déploiement, domaines
    métier séparés proprement (inventaire, supervision, alertes,
    incidents, automatisation, IA, coûts, facturation).
  - Séparation **Control Plane** (SaaS central : web, API, workers) /
    **Data Plane** (connecteurs chez le client, connexions sortantes
    chiffrées, mTLS).
  - Extraction de composants en services séparés uniquement si la charge
    ou les besoins opérationnels le justifient, avec un ADR dédié.
- **Conséquences :**
  - Positives : déploiement simple, transactions ACID locales, tests
    d'intégration facilités, mise en route rapide.
  - Négatives : mise à l'échelle par réplication du monolithe ; un
    module défaillant peut affecter l'ensemble (mitigé par les files
    Celery et les circuit breakers).
- **Alternatives rejetées :** microservices dès le départ (complexité
  prématurée) ; monolithe sans séparation de domaines (dette de
  modularité).
