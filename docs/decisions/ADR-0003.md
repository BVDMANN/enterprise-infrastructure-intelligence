# ADR-0003 — PostgreSQL + Redis + Celery

- **Statut :** Accepté (2026-11-24, PHASE 0)
- **Contexte :** la plateforme a besoin d'une base relationnelle forte
  (inventaire, relations, audit), d'un cache et d'une file de tâches
  pour les traitements asynchrones (synchronisations, rapports,
  notifications), et d'un stockage de métriques adapté aux séries
  temporelles.
- **Décision :**
  - **PostgreSQL 16** pour les données métier (inventaire, utilisateurs,
    alertes, incidents, workflows, audit, facturation).
  - **Redis 7** pour le cache, les tâches et les mécanismes temporaires.
  - **Celery** pour les traitements asynchrones (broker Redis).
  - **Ne pas stocker indéfiniment les métriques dans PostgreSQL.**
- **Conséquences :**
  - Transactions ACID et contraintes d'intégrité pour le métier ;
    files découplées pour la scalabilité des traitements.
  - Opérations : sauvegardes PostgreSQL chiffrées + restauration
    testée ; Redis persistant uniquement pour les résultats Celery.
- **Alternatives rejetées :** base NoSQL comme base métier (perte des
  garanties relationnelles pour l'inventaire et l'audit) ; file de
  tâches ad hoc en base (mauvaises performances, pas de retry/backoff).
